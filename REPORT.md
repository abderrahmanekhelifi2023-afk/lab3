# Лабораторная работа № 3: линейные модели

## Данные и подготовка

`Student_Performance.csv` содержит 10 000 строк, пять признаков и целевую
переменную `Performance Index`. Пропусков нет. Признак
`Extracurricular Activities` преобразован по правилу `Yes → 1`, `No → 0`.
Все строки сохранены, включая 127 точных дубликатов. Целевая переменная не
масштабировалась. Разбиение `train_test_split(test_size=0.2, random_state=42)`
дало 8000 обучающих и 2000 тестовых наблюдений.

`german.csv` загружен с разделителем `;`. В нём 1000 строк, 20 признаков и
бинарная цель `Creditability` в первом столбце: 700 значений `1` и 300 значений
`0`. Пропусков и полных дубликатов нет. Использовано разбиение 80/20 с
`random_state=42` и `stratify=Creditability`: в train 800 наблюдений
(560 единиц и 240 нулей), в test 200 (140 единиц и 60 нулей).

Для каждого набора отдельно применён `StandardScaler` ко всем признакам.
Средние и стандартные отклонения вычислялись только по train; test
преобразовывался тем же обученным scaler. Все классификаторы получили
одинаковые преобразованные обучающую и тестовую части. Числовые коды категорий
German Credit оставлены числовыми, без one-hot кодирования. Это ограничение:
числовое расстояние между кодами не обязательно отражает различие категорий,
особенно для KNN.

## Гипотезы и эксперименты

Проверялись две гипотезы: пакетный градиентный спуск после масштабирования
уменьшает обучающую ошибку; собственная логистическая модель может быть
конкурентоспособна с готовыми моделями на одном и том же разбиении.

Собственная линейная регрессия обучалась с нулевыми весами и смещением,
`learning_rate=0.05`, `epochs=800`. На каждом шаге градиенты MSE вычислялись по
всей обучающей выборке. В историю записывалась MSE после обновления параметров.

Собственная логистическая регрессия также начинала с нулевых параметров и
обучалась без регуляризации: `learning_rate=0.1`, `epochs=1000`. Использованы
пакетный градиентный спуск, устойчивая сигмоида и BCE по логитам через
`np.logaddexp`. История BCE записывалась после обновления. Положительный класс —
`1`; предсказание равно `1` при вероятности не меньше `0.5`. Обе собственные
модели реализованы на NumPy без готовых линейных моделей sklearn внутри обучения.

На тех же данных проверены три готовые модели:

- `LogisticRegression(max_iter=1000, random_state=42)`: `solver='lbfgs'`,
  L2-регуляризация с `C=1.0`;
- `DecisionTreeClassifier(random_state=42)`: критерий Gini, глубина не ограничена;
- `KNeighborsClassifier(n_neighbors=5)`: равные веса соседей, евклидово расстояние
  (`metric='minkowski'`, `p=2`).

Готовые модели возвращаются из `compare_classical_models` по контракту
`BaselineComparisonResult`; собственная логистическая оценена отдельно на том
же test. Другие разбиения и варианты гиперпараметров в этом эксперименте не
сравнивались.

## Выводы

Обучающие MSE и BCE уменьшились, что подтверждает первую гипотезу для выбранных
данных и параметров. Линейная регрессия достигла test MSE около 4.083 при
train MSE около 4.170.

На данном разбиении собственная логистическая модель превзошла дерево и KNN
по всем пяти метрикам. Accuracy выше результата дерева на 8.5 процентного
пункта, KNN — на 5 пунктов. С готовой логистической моделью совпали Accuracy,
Precision, Recall и F1; ROC-AUC собственной модели немного ниже:
0.808095 против 0.808571.

Близость двух логистических моделей согласуется с одинаковым линейным видом
границы решений. Их вероятности могут различаться из-за разных методов
оптимизации и регуляризации: собственная модель не регуляризована, готовая
использует L2. Возможные причины более слабых результатов дерева и KNN —
высокая вариативность неограниченного дерева на небольшой выборке и
чувствительность KNN к расстояниям между числовыми кодами категорий.
Эти причины являются интерпретацией, а не отдельно проверенными эффектами.
Один фиксированный split не доказывает преимущество модели на других
разбиениях или при другой подготовке признаков.

## Воспроизводимость

Из директории `lab3` выполнить:

```console
python linear_models.py
```

Скрипт читает два CSV из своей директории, повторяет подготовку и обучение,
выводит метрики и контрольные значения потерь, а также записывает
`experiment_results.json`. В JSON находятся `linear_regression.test_mse` и
`classification` с четырьмя наборами метрик: `own_logistic`,
`logistic_regression`, `decision_tree`, `knn`.

Среда получения приведённых результатов:

- Python 3.12.14;
- NumPy 2.3.5;
- pandas 3.0.1;
- scikit-learn 1.9.1.

Разбиения и дерево используют `random_state=42`, собственные модели начинают
обучение с нулевых параметров. Параметры обучения и параметры готовых моделей
приведены выше. Контракты из `grader_contracts` сохранены без изменений.
